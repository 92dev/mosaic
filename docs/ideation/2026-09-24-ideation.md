## 3. The four defects — corrected design

### 3.1 Context (6.0)

Tier A (always-on, ≤ 40 lines): `.omp/rules/mosaic-core.md` with `alwaysApply: true` (NOT `RULES.md`: user-level `RULES.md` shadows a project `RULES.md` under the shared name `RULES`). Content = the integrity/evidence rules, rewritten so "verify" means *attributable evidence for the exact state claimed; reuse still-valid outputs; rerun only after relevant state changed* (critic C14). Plus `AGENTS.md` ≤ 25 lines: what the repo is, precedence, and one instruction: "read `rule://map` before any change".
Tier B (rulebook): `map` (≤ 60 lines), `plan-triage`, `git-flow`, `dispatch`, `review-loop`, `verification`, `records`, `registries`, `plan-home`, `stack`, `human-gates`, `writing-for-the-reader`. Rule: **a procedure step that depends on a rule says "read `rule://<name>` now"** — a citation alone loads nothing (F6). That is the fix for F4, made mechanical: `doctor` fails a skill that edits a governed path without a "read `rule://records`" step before it.
Tier C (per-agent always-on): `targeted-tests.md` with `agents: [executor, "*-reviewer"]`, `alwaysApply: true`. One role-relative **precedence contract** (≤ 8 lines) in every agent body: executor finishes its authorized task inside `files:`; guards constrain but never expand that authority; reviewers never fix; the orchestrator owns routing and whole-repo verification; a conflict returns to the orchestrator quoting the exact rule/task clause (critic C13).
Family-specific prompt text (Fable finish-the-task, Astra transparency) goes in AGENTS.md only when it must fire unprompted for the *orchestrator*; agent bodies stay family-neutral because role ≠ model (config overrides frontmatter; critic C17). Model-specific tuning lives in `modelRoles`/effort.
Budgets are targets to be *measured* in the loop rig from the JSON event stream (realized prompt tokens, read turns), not inferred from file line counts (critic C16).

### 3.2 Gaps (6.1)

Template: "Verification gaps" → "Unverified" (evidence, not registry draft). Planning never writes G-entries or triggers.
Close-out **triage is owned by the orchestrator, before requesting sign-off, as a named step in `execute`** that first says "read `rule://records`". Input = acceptance criteria + verification outputs + unresolved findings + Unverified. Order of tests, one evidenced disposition per leftover:
1. **Defect check first**, regardless of whether the file was touched: any unmet current acceptance criterion, or a bug found in code, is a defect. Defects in this plan's scope go back into the REVISE loop (≤2, then human) — never deferred by relabeling. A defect outside scope becomes a new plan proposal through the normal `draft` path (no new `queued` status; critic C11) or, if trivial, the light path.
2. Then the **full record-routing table** (Decision / Obligation G-x / Pitfall / Open question / Product / "no retained obligation" with reason). An obligation must state `when:` (a checkable condition: path glob, event, plan kind), why it is not actionable now, and why it is outside current acceptance — a syntactically valid `when:` is not enough (critic C9).
3. **Cannot classify** → surfaced in the sign-off brief; blocks that entry only, not the rest of the plan.
The reviewer's checklist gains one item: reject a close-out whose dispositions are missing or unsupported. lint-ledgers gains: G-entry must have `when:`; open questions live in `open-questions.md` and promotion to G-x requires a cited human ruling.
Same contract applies to *any* procedure that creates a G-entry (light path, gap-evaluate).

### 3.3 Meta adherence (6.2)

Layer 1 — deterministic gates own enforcement: `lint-ledgers` (schema, ids, `when:`, archive/active consistency) + `doctor` (unique rule names, unresolved `rule://`/link references, "read rule://records" step present before governed edits, generated-port drift, advisory duplicate-phrase report). Three outcomes: PASS / FAIL / CANNOT-EVALUATE (exit 0/1/2; the reference harness proves the *principle* with its UNPROVEN state, not the protocol).
Layer 2 — procedures read the rule at the point of use: every skill step that mutates a governed class starts with "read `rule://records`" (this is what F4 lacked).
Layer 3 — TTSR `records-guard` as a **best-effort, once-per-session reminder**, not a gate: scope enumerated from the doc-class table, both `edit` and `write`, both path frames (`docs/**` and `*/docs/**`), including `docs/gaps/**`, `docs/plans/**`, `docs/architecture/pitfalls.md`, `.omp/**`; `interruptMode: tool-only` (abort + retry with the rule body injected). The critic probed the v0 scope with `omp ttsr test`: `docs/gaps*.md` missed `docs/gaps/G-1.md`, member ledgers, and all `write`s. Set `ttsr.repeatMode: after-gap` in the project config overlay if re-arming is wanted.
Layer 4 — lifecycle sweeps: `/checkup` (deterministic `preprocess.ts` over session events → candidates → single-session audit; adds mosaic classes "governed file edited without a preceding `rule://records` read", "lint FAIL ignored", "G-entry minted without `when:`"). Run on demand and after every N landed plans.
Judged `question:` rules: **advisory only**, scoped `agents: main`, `scope: text`, require `ttsr.judge: on` (or a TypeSafe judge). Questions limited to properties visible in the output itself (critic C4): e.g. "Does this decision brief use an internal id (G-x, P-x, NNNN, agent name) without a plain-language restatement?" — not "did tests really run".
No standing advisor/librarian: `advisor:` attaches to a whole agent session, not a phase (critic C6). Revisit only if loop evidence shows a miss the four layers don't catch.

### 3.4 Human explanation (6.3)

`human-gates` rule (rulebook), read by `plan` (approval request, leftovers digest) and `execute` (sign-off brief) — **only at actual decisions**; round reports stay informational (critic C15). Content: the adopted infer-dist rules (claim first in ordinary words; identifiers after, once, in parentheses; no session-invented labels; plain stays as true as the code; each sentence checkable from the previous), aidlc's triad (what was produced / what to look at / what happens after approval), and a mosaic jargon→plain table. Scope: explain concepts the reader hasn't used in this session; vocabulary the operator uses is known (F9). infer-dist.txt → `rule://writing-for-the-reader`, on demand.
Enforcement: rubric in the loop rig (S2) + optional advisory `question:` rule on `main`. Outbound artifacts (PR bodies, docs) are checked at their delivery step by the reviewer, not by a text judge.
