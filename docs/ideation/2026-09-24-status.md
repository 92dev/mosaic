## What changed in the design because of evidence (all applied in the mosaic fixture)

- `plan-triage` now has three vehicles: **inline** (mechanical edit, orchestrator edits directly) / light path / plan. Evidence: baseline S4 dispatched executor + two reviewers for one word.
- `execute` step 7: a defect is in scope only when an acceptance criterion requires its absence; other defects become a proposal and do not block close-out. Evidence: mosaic-v0 GPT S1 blocked on a T2 amendment.
- `records-guard` body: "a `Trigger:` (or `when:`) line naming a checkable condition". Evidence: GPT wrote `Trigger: when:`.
- Executor rule 6: skills/process rules in the prompt are orchestrator procedures; do not read them. Evidence: executors read `skill://execute` (both harnesses).
- Skills: "read each named rule once per session". Evidence: repeated `rule://` reads across steps.
- `.omp/config.yml` in the harness defines the semantic roles (`@templated`, `@critic`, `@review-claude`, `@review-gpt`, `@judgment`, `@balanced`, `@smol`). Evidence: "No model selected" when the roles were undefined.
- S1 prompt pre-authorizes dispositions (mosaic's triage happens before sign-off, so "already signed off" was ambiguous). S3's pitfall text became a genuine trap (the `uv --project` cwd defect measured while wiring the rig) because the first text duplicated workflow §6 and Opus rightly refused it.

## Rig findings worth keeping

- In omp, only root `AGENTS.md` is injected; root `CLAUDE.md` is shadowed (same depth, same priority). The baseline's cold start was therefore `AGENTS.md` + whatever the model chose to read (`CLAUDE.md`, `workflow.md` whole).
- `--profile` isolates auth too; isolation is done with `overlay.yml` (`disabledProviders`, no advisor, no memory).
- `cp` rewrites relative symlinks unless `verbatimSymlinks: true` — the rule symlinks would have pointed at the source fixture.
- The `.omp` TS lint hook in the kit could not be hand-invoked (P-31 class); both fixtures now have an argv CLI with exit 0/1/2.
- `finalText` misses briefs delivered before a closing message; `metrics.assistantTexts` keeps every assistant text block.

## Cost notes

Mosaic S1 costs ~1.7–1.9× the baseline because close-out now reviews the dispositions (skill step 7 sends them through the review loop) and in-scope notes go through executor + review. Both are the design, not waste, but tunable: one disposition-review cycle instead of two; allow the orchestrator to apply mechanical in-plan fixes inline. Everywhere else mosaic costs less (S2, S3, S4, S5).
