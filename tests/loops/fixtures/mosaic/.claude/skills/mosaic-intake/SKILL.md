# /mosaic-intake — Investigate requests before routing work

1. Read `docs/process/intake.md`; read `docs/process/plan-triage.md`; read `docs/process/records.md`; read `docs/process/tracker.md`.
   **Start one intake session:** commands run from the link-repo root in replay mode. Generate the writer token once per session as `w-<8 hex from /dev/urandom>` (`bun -e 'console.log("w-" + require("node:crypto").randomBytes(4).toString("hex"))'`), record it in the digest, and reuse it for every item and retry. Never derive it from timestamps, content, hostnames, or local paths.
2. **Harvest the complete queue:** run `bun tools/tracker.ts list --state triage --label intake`; for an explicit `todo` argument substitute `--state todo`. Require the `{"complete":true}` trailer. An unavailable/incomplete inventory is a reported limitation, not an empty queue.
   For each item run `bun tools/tracker.ts get <key>` to collect its title, body, comments, and attachments; inspect attachments rather than infer their content. Record unreadable evidence explicitly.
   Run `bun tools/tracker.ts receipt <key>` to identify prior verdict comment ids and their exact bodies. Exclude only unchanged adapter-authored receipts from the source fingerprint; a human edit to a receipt still counts.
   Compute SHA-256 over a deterministic JSON array `[title, body, comments, attachments]`: comments are `[id, sha256(body)]` pairs sorted by id; attachments are their full metadata and content hashes sorted by id. Use the same encoding on every run; if content cannot be read, record that limitation rather than invent a hash.
   Record each repo as a self-identifying pair `<repo root>=<HEAD>` (from `git -C <repo> rev-parse --show-toplevel HEAD`) in one record before any dispatch; ASSESS and REFUTE report the root→HEAD pairs they observed, never a positional list. Record any in-scope working-tree changes as unverified state; they prevent reuse of a previous verdict.
3. **Reuse only unchanged evidence:** read the last verdict for each item. Skip investigation only when its source fingerprint and every touched repo revision still match, its scope is known, and no in-scope working-tree changes or unreadable source prevent comparison. Otherwise investigate again; prior verdicts are leads, not evidence.
   For unchanged held items, carry the owner/question/resume condition into the digest without re-asking the question. For other skipped items, echo the existing verdict and receipt id rather than posting a duplicate.
4. **Investigate in parallel:** dispatch one `ticket-investigator` via Claude Code subagent dispatch in ASSESS mode per changed item, using `@investigator`. Supply the full source, fingerprint, per-repo revisions, known code/doc pointers, and only relevant project reproduction protocols under `docs/intake/` (none are required).
   Record the actual ASSESS model family. For `implemented` other than `no`, or a proposed LOW, dispatch REFUTE using the other family's configured reviewer role, with the ASSESS verbatim and the identical source/revisions. Name both actual families in the investigation evidence.
   Apply `docs/process/intake.md`'s REFUTE gate before settling.
5. Read `docs/process/registries.md`. **Settle after registry coverage:** dispatch `registry-scout` via Claude Code subagent dispatch with each item's reading, paths, and public contracts. Existing plans may cover the request; a draft is not proof of implementation.
   Settle the record using `docs/process/intake.md`, the ASSESS, REFUTE, and registry evidence. Keep PRODUCT-DECISION in the blocking question/reason, not the risk enum. For held work, name the assignee or requester as owner; if neither is known, say `owner: unassigned — human assignment needed`; include the blocking question and an observable resume condition.
6. Read `docs/process/tracker.md`. **Publish the proposed verdict:** re-fetch the item and recheck scoped revisions before posting. Changed evidence returns to step 3; do not stamp old findings with a new fingerprint.
   Render the exact INTAKE VERDICT block from `docs/process/intake.md` to a temporary file outside the repos, then run `bun tools/tracker.ts comment <key> --file <path> --writer <token>`. The adapter sets the managed `intake:<disposition>` label from that block; it preserves unrelated labels. Keep returned comment/event ids for the digest.
   On an uncertain write, read back with `get <key>` and `receipt <key>` before retrying; report refused/unavailable writes without claiming a posted verdict. Delete temporary verdict files after read-back. Do not edit code, plans, registries, or create a markdown intake ledger.
7. Read `docs/process/human-gates.md`. **Present the human digest:** start with a plain TL;DR of the proposed outcomes and the decision needed. Echo each complete verdict block with its evidence and posted/reused receipt id; include limitations and only blocking questions. Record the writer token and session start timestamp once. State what will happen after each answer.
8. **Stop at the digest** per `docs/process/intake.md`'s human hold. After the answer, route through `docs/process/plan-triage.md`; the chosen procedure supplies implementation, review, and landing steps.
